# Что умеет система

Актуально на 31.08.2026. Файл описывает **всю систему**, а не только
первоначальный скрипт по eBay: с тех пор пайплайн развернулся, и главным
входом стал не поиск по eBay, а перечень московского спроса.

---

## 0. Одной строкой

Система отвечает на вопрос **«что купить на eBay, чтобы перепродать в
Москве с кратностью»**. Делает это не сканированием eBay вслепую, а от
спроса: сначала из локального архива 146 575 московских продаж
перечисляется, за что Москва реально платит, и уже этот список идёт
искать на eBay.

Что есть в наличии прямо сейчас:

| ресурс | объём |
|---|--:|
| архив проданных лотов Мешка | 146 575 продаж за 179 дней (04.03–29.08.2026) |
| московский want-list | 837 позиций |
| индекс карточек МаркетВинила | 98 файлов релизов + 9 файлов мастер-релизов |
| база сделок | 9 записей, все в статусе `seen` |
| размер базы | ~618 МБ (в git не попадает) |

## 1. Развёрнутый пайплайн — главный вход

```bash
python3 tools/wantlist_sweep.py --top 100
```

Берёт позиции московского want-list и ищет каждую на eBay. Никакого
сканирования 30 лейблов вслепую.

**Две стадии, чтобы не жечь запросы.** Сначала дешёвый поиск по каждой
позиции с отсевом по самому широкому потолку (2x); детальные запросы
тратятся только на выживших, и их число ограничено.

**Ключи:**

| ключ | что делает |
|---|---|
| `--top N` | сколько позиций обойти (по умолчанию 100 из 837) |
| `--order ceiling\|money` | `ceiling` — по потолку ставки (умолчание); `money` — по обороту позиции |
| `--countries US` | страны продавцов |
| `--jazz` | только джазовые позиции |
| `--max-details N` | потолок детальных запросов за прогон |
| `--max-sellers N` | скольким продавцам проверять инвентарь (партии) |
| `--no-inventory` | не проверять инвентарь — быстрее, но партии считаются по старому узкому критерию |
| `--push` | отправить находки в уведомления |

**Почему `ceiling` по умолчанию:** want-list отсортирован по деньгам, а
гейт благоволит дорогим позициям. Сортировка по обороту работала против
собственного гейта.

**Что выдаёт:** список проходных лотов с ценой, потолком ставки,
кратностью, грейдом, прибылью в рублях, пометкой «партия/одиночно» и —
обязательно — флагами «сверить глазами». Плюс аудит по правилу 2 (см. §7).

## 2. Архив Мешка — фундамент всего

```bash
python3 meshok_archive.py --status          # что уже скачано
python3 meshok_archive.py --days 30         # докачать
python3 meshok_archive.py --jazz            # только джаз-разделы
```

Локальный архив проданных лотов. Почему локальный, а не запрос на лот:

* lookup становится мгновенным — при прогоне eBay сеть к Мешку не нужна;
* появляется **статистика рынка**, а не точечные цены;
* прогон перестаёт зависеть от доступности сайта в этот момент.

**Как обходится потолок выдачи.** Жёсткий потолок — 1400 записей на
выборку (7 страниц по 200), один день в него не влезает.
Партиционирование адаптивное: один запрос `includes.stats` отдаёт точные
счётчики по подкатегориям дня, и уже по ним строится план — крупные
подкатегории берутся по одной, слишком крупные дробятся по цене, весь
остаток забирается одним запросом. ~12 запросов на день вместо 26+.

Глубина архива продаж — **ровно 179 дней**, дальше сайт не отдаёт.
Последние 3 дня перечитываются при каждом запуске (лоты доторговываются).

## 3. Московский want-list — перечень спроса

```bash
python3 moscow_wantlist.py
```

Строит список того, за что Москва платит:

* `ru_sold_n >= 3` за окно — доказанная ликвидность, а не догадка;
* медиана `>= 3 500 ₽` — ниже покупка не окупается ни при какой цене;
* ранжирование по **медиана × число продаж** — по деньгам, а не по цене.
  Одна продажа за 20 000 ₽ хуже семи по 5 000 ₽: во вторую можно попасть,
  в первую — нет.

Результат: **837 позиций**. По одному джазу выходит ~37 — рынок дорогого
джаза в Москве узок настолько; отсюда умолчание строить список по всему
винилу, а джаз только помечать флагом.

Внутри лежит **сопоставитель названий** — самая переписываемая часть
системы (четыре итерации, каждый класс ложных срабатываний найден
запуском, ни один — тестами). Проверяет позицию исполнителя в заголовке,
долю совпавших слов альбома, отдельно обрабатывает одноимённые альбомы и
отсеивает неверные форматы (`disc only`, `no cover`, `warped`).

## 4. Экономика и гейт

**Landed cost:** цена лота + доставка до форвардера + карго в РФ
(0.3 кг × $22/кг для одиночной пластинки, 0.35 кг для gatefold) + издержки
сбыта 550 ₽, курс 100 ₽/$.

**Двойной гейт — оба условия обязательны, они отвечают за разное:**

| условие | за что отвечает | значение |
|---|---|---|
| кратность | вероятность **не** получить прибыль (риск состояния) | 2.0 / 2.5 / 3.5 по грейду и ликвидности |
| абсолютный пол прибыли | окупает ли сделка само действие | 2 500 ₽ **валовой** прибыли |

Кратность одна не годится: 3x от 1 500 ₽ — это работа за 1 000 ₽.
Абсолютная прибыль одна тоже: она не отличает запечатанную пластинку от
безымянного G+.

Прибыль берётся валовая, а не матожидание: домножать пол ещё и на
вероятность продажи — двойной счёт.

**Сверх гейта — три сторожа:**

1. лоты дороже $60 уходят на ручную сверку до ставки, без исключений;
2. позиции с межквартильным разбросом цен ≥ 2.5x помечаются «под одним
   названием разные прессы» — медиана такой позиции не называет цену
   конкретного лота (см. §7);
3. потолок цены лота — $300.

**Модель цены** (`ru_price_model.py`) умеет:

* мерить коэффициенты грейдов **по данным**, а не брать из конфига
  (замерено: NM 1.96 против 1.4 в конфиге, VG 0.38 против 0.55);
* при трёх и более прямых наблюдениях в нужном грейде брать их медиану
  напрямую и не трогать рыночный коэффициент вовсе;
* никогда не предсказывать цену выше максимума собственной выборки.

## 5. Аналитика по архиву

Всё это — запросы к уже собранным данным, а не новые сборы.

| команда | что даёт |
|---|---|
| `python3 tools/moscow_market_report.py` | отчёт по рынку: доля джаза, премия за пресс, медианы по грейдам, динамика |
| `python3 tools/wantlist_breakdown.py` | 837 позиций в семи разрезах: категория, год, страна, грейд, ликвидность |
| `python3 tools/categories_ranking.py` | сравнение 9 категорий Мешка по деньгам **выше собственного порога окупаемости** |
| `python3 tools/value_my_stock.py` | оценка собственного склада: за сколько и где продавать то, что уже лежит |

Главные измеренные числа: джаз — 10.3% рынка винила, медиана 1 300 ₽;
премия за оригинальный пресс в Москве — **1.19x**, а не 10–20x, как
предполагалось; винил — 117 млн ₽ выше порога, третье место из девяти
категорий и **первое среди тех, где не нужна экспертиза против подделок**.

## 6. МаркетВинила — готово, но не запущено

```bash
python3 tools/build_mv_release_index.py            # индекс карточек
python3 tools/mv_price_survey.py                   # сам срез
```

**Находка, на которой всё держится:** id в URL МаркетВинила — это id
Discogs. Значит, поиск не нужен вовсе: по release_id, который резолвер уже
знает, URL карточки **вычисляется**. Это важно, потому что поиск на
МаркетВинила закрыт их же robots-политикой.

Срез стратифицированный: по 20 позиций из каждой ценовой страты (3.5–6,
6–10, 10+ тыс) плюс 20 джазовых отдельной строкой — усреднение по всем 80
скрыло бы ровно то, ради чего собирали.

Ищет сначала конкретный пресс, потом мастер-релиз, и **возвращает ярлык
того, что нашлось** — цена пресса и цена альбома это разные величины.

**Статус: не запущен.** Канонический адрес закрыт Cloudflare Turnstile,
который эта машина пройти не может. Обходной путь найден и сознательно
отклонён (`docs/ru_market_notes.md` §6). Запускается одной командой с
машины, где браузер проходит проверку честно.

Покрытие каталога замерено заранее: 30 карточек на 53 резолвящихся
позиции, причём джаз покрыт лучше всех — 11 из 15.

## 7. Два правила, которые выше кода

Полный текст — `docs/УСТАВ.md`.

**Правило 1. Уровень измерения не подменяется.** Величина, измеренная на
одной популяции, не переносится на подпопуляцию без проверки. Прямое
измерение главнее коэффициента. Предсказание не бывает выше максимума
собственной выборки.

**Правило 2. Ноль проверяется так же придирчиво, как находка.** Каждый
нулевой прогон обязан ответить: «посмотрела и отказала» или «не
посмотрела». Поэтому обход печатает разбивку отказов по классам, а не
строку «0 находок».

**Следствие, действующее бессрочно: пуш только после сверки глазами.**
Однажды 51 «находка» ушла в Телеграм до проверки, и все 51 оказались
ложными срабатываниями сопоставителя.

Оба правила уже окупились. Последний случай: единственный лот, прошедший
двойной гейт, опирался на медиану 7 600 ₽ по трём продажам — 1 734 ₽
(японский репресс), 7 600 ₽ (UK 1968) и 28 000 ₽ (UK 1968 mono 1st press).
Три разных товара, а не три продажи одного.

## 8. Учёт сделок

```bash
python3 -m vinyl init
python3 -m vinyl deal new 128040567510 --max-bid 25 --status bid
python3 -m vinyl deal update 1 --status sold --sold-price-rub 10000
python3 -m vinyl deal list --status won
python3 -m vinyl stats
```

Жизненный цикл: `seen → bid → won|lost → shipped → received → graded →
listed → sold|unsold`. Нужен для калибровки: без закрытых сделок бэктест
не имеет входных данных. Сейчас записано 9 сделок, все в статусе `seen` —
**подтверждённых покупок ноль**.

## 9. Уведомления

```bash
python3 notify.py "проверка"
```

Драйвер выбирается сам: `telegram`, если в `.env` есть `TG_BOT_TOKEN` и
`TG_CHAT_ID`; иначе `ntfy.sh` — без регистрации и токенов.

Тема ntfy фактически публична: кто знает строку темы, тот читает
уведомления. Поэтому тема генерируется случайной на 160 бит и лежит в
`.env`, а в пуш кладутся **только ссылка на лот и цифры** — никаких
ключей, токенов и адресов.

## 10. Старый вход: поиск по eBay напрямую

Не удалён и работает, но это прежний пайплайн — перебор безграничной
стороны в надежде попасть в дефицитную (385 проверенных лотов, ноль
попаданий).

```bash
python3 ebay_vinyl_3x_finder.py                        # обычный режим
MAX_PRICE_USD=1 python3 ebay_vinyl_3x_finder.py        # дешёвый
GOLDEN_MIN_PRICE=40 GOLDEN_MAX_PRICE=210 python3 ebay_vinyl_3x_finder.py
AUCTION_ENDING_HOURS=18 MAX_LANDED_USD=11 python3 ebay_vinyl_3x_finder.py
```

Охват: ~30 джазовых лейблов × 3 сортировки eBay, только продавцы из США.

## 11. Чего система НЕ делает — и не будет

Заморожено сознательно, возвращаться не к чему:

* **не ставит ставки автоматически** — только уведомляет;
* **не определяет пресс по фото** (vision) — закрыто; фото остаются нужны,
  но для другого: определять реальное состояние;
* **не считает таможню**;
* **не обходит защиту сайтов** — ни солверов, ни сторонних прокси, ни
  подставленных кук, ни походов по запрещённым в robots адресам;
* **не скрейпит историю продаж Discogs** через залогиненную сессию;
* **не делает бэктест** — до первых 10 закрытых сделок он не на чем;
* ансамблевая оценка ликвидности и расширение списка лейблов заморожены:
  охват задаёт спрос, а не перечень лейблов.

## 12. Тесты

16 тестовых файлов, все офлайновые — сеть не нужна:

```bash
for f in test_*.py; do python3 "$f"; done
```

Важная оговорка, которую стоит держать в голове: **ни одна из четырёх
серьёзных ошибок этого проекта не была найдена тестами.** Все четыре
нашлись при запуске на живых данных, а три из четырёх — при попытке
объяснить словами, откуда взялось конкретное число. Тесты защищают от
регрессий, но не от неверно применённой величины.
