# ebay_vinyl_3x_finder.py — что умеет скрипт

Актуально на 30.08.2026 (после доработки по ТЗ).

Скрипт ищет джазовый винил на eBay, сопоставляет каждый лот с конкретным
релизом на Discogs, считает landed cost (цена + доставка до форвардера +
пересылка в РФ) и маржу с поправкой на состояние, выдаёт вердикт
REJECT / WATCH / PASS.

---

## 1. Режимы поиска

| Режим | Что ищет | Как включить |
|---|---|---|
| **1. Обычный** | Buy It Now + аукционы, цена лота ≤ $10 | по умолчанию |
| **2. Дешёвый** | то же, но со своим порогом цены (напр. ≤ $1) | `MAX_PRICE_USD=1` |
| **3a. Аукционы на закрытии** | только AUCTION, закрытие в ближайшие N часов, бюджет по **landed до форвардера** (без международного плеча) | `AUCTION_ENDING_HOURS=18 MAX_LANDED_USD=11` |
| **3b. BIN / Best Offer** | только FIXED_PRICE, без ограничения по времени, тот же landed-бюджет | `FP_MAX_LANDED_USD=11` |
| **4. Золотой** | BIN / Best Offer, ценовой **коридор** $40–210, жёсткий порог margin ≥ 3x (без grey zone) | `GOLDEN_MIN_PRICE=40 GOLDEN_MAX_PRICE=210` |

Дополнительные переменные: `GOLDEN_MIN_MARGIN` (по умолчанию 3.0),
`DEBUG_VERDICTS=1` (см. §5).

Пример запуска:

```bash
export EBAY_CLIENT_ID="..." EBAY_CLIENT_SECRET="..."
python3 ebay_vinyl_3x_finder.py                          # Режим 1
MAX_PRICE_USD=1 python3 ebay_vinyl_3x_finder.py          # Режим 2
GOLDEN_MIN_PRICE=40 GOLDEN_MAX_PRICE=210 python3 ebay_vinyl_3x_finder.py   # Золотой
```

**Охват:** ~30 джазовых лейблов × 3 сортировки eBay (bestMatch /
newlyListed / endingSoonest, до 100 лотов на запрос) — намеренно не
только Best Match, потому что он систематически прячет вниз именно
непримеченные лоты. Только продавцы из США. Бандлы и нежелательные
форматы отсеиваются по ключевым словам.

## 2. Обработка одного лота

1. **Извлечение каталожного номера** из заголовка по regex-паттернам:
   ECM, BLP/BST, ASD/AS, V/V6, SD/CS/SN, PR(LP/ST), RLP, CTI, SC[SC],
   OJC, WP/WPS.
2. **Резолв в конкретный Discogs release:** точное совпадение catno →
   дизамбигуация по стране прессинга / названию / reissue-меткам →
   ансамблевая (взвешенная по ликвидности) оценка, если несколько
   легитимных прессов делят один catno.
3. **Жанровый фильтр** — если у резолвнутого релиза заполнен genre и в
   нём нет «Jazz», лот отбрасывается сразу, до трат на дальнейшие вызовы
   Discogs и eBay.
4. **Чтение полного описания лота** через eBay item detail — вытаскивает
   реальный грейд продавца («RECORD: VG+ / COVER: G+»), которого почти
   никогда нет в заголовке, и пересчитывает маржу по нему.
5. **Расчёт landed cost** = цена + доставка до форвардера (из листинга
   либо fallback по стране) + международная пересылка по весу.
6. **Вердикт** REJECT / WATCH / PASS по порогам из конфига, с поправкой
   на состояние.

---

## 3. Оценка достоверности резолва

Новое поле **`resolution_confidence`** — `high` / `medium` / `low`.

`low` ставится в двух случаях:

- **Ансамблевый выброс ликвидности.** Топ-по-ликвидности кандидат сам по
  себе в ≥ 2.5x дороже медианы всех остальных кандидатов. Это ровно тот
  паттерн, когда дорогой культовый **оригинал** подменяет собой реальный
  дешёвый репресс из лота (подтверждено на Eric Dolphy ×2 и Shamek
  Farrah).
- **Каталожного номера в тексте лота нет вообще.** Резолв строится на
  чистом фаззи-поиске по названию, который может вернуть любой из
  десятков одноимённых переизданий (Sonny Clark «1588», Blue Train
  «1577»).

При `resolution_confidence = low` вердикт **понижается на ступень**:
PASS → WATCH, WATCH → REJECT. Скрипт не пытается угадать «более
правильную» цену без фото лейбла — он честно снижает доверие.

Отдельно: в **degraded mode** (см. §6) PASS не выдаётся вообще, максимум
WATCH.

## 4. Вывод

**Консоль (по ходу прогона):** каждая находка WATCH/PASS печатается сразу
же — с кликабельной ссылкой, временем до закрытия для аукционов и
отдельной строкой «до форвардера $X» рядом с полным landed (в Режиме 3 и
Золотом это разные величины).

**`candidates_<дата>.csv`** — результат прогона.
**`decisions_log.csv`** — накопительная история across прогонов, дедуп по
URL, колонки исхода сделки заполняются вручную после факта.

Колонки прозрачности вердикта (дописаны в конец схемы, старые файлы не
ломаются):

| Колонка | Значение |
|---|---|
| `resolution_confidence` | high / medium / low (см. §3) |
| `candidate_count` | сколько прессов участвовало в ансамблевой оценке |
| `degraded_pricing` | true, если median = low×2, а не реальная подсказка Discogs |
| `pricing_source` | `price_suggestions` или `degraded_2x_low` |

## 5. Надёжность и эксплуатация

- **Retry с backoff:** до 4 попыток с паузами 2/4/8 с на 429 и 5xx, плюс
  на сетевые ошибки. Когда попытки исчерпаны — печатается сообщение, лот
  не теряется молча.
- **Кэш Discogs в рамках прогона:** поиск и статистика кэшируются, один и
  тот же релиз не запрашивается повторно. Неудачи не кэшируются.
- **Валидация конфига на старте:** опечатка в порогах (например
  `GOLDEN_MIN_PRICE > GOLDEN_MAX_PRICE`, отрицательный бюджет) роняет
  скрипт сразу с внятным сообщением, а не даёт тихо неверные вердикты
  весь прогон.
- **`DEBUG_VERDICTS=1`** — печатает причину каждого отсева
  (bundle / no_release / no_stats / каждый вид reject), а не только
  находки.
- **Обновление eBay-токена** на лету при 401 — повторяется ровно тот
  запрос, а не падает весь прогон.

## 7. Чего скрипт принципиально не может

### Главное: маржа считается от мирового рынка, а продавать — в Москве

Все `margin_*` в выводе посчитаны против **Discogs marketplace** — это
глобальный рынок, **продавать на котором из России нельзя** (buy-only
с 2022 г.). То есть маржа отвечает на вопрос «насколько ценен этот пресс
глобально», а **не** «сколько я реально выручу в Москве».

Реальный канал сбыта (МаркетВинила / Мешок / VK-группы / скупка) кратно
тоньше и дешевле. Разрыв бывает в разы: на Bennie Green — Walking Down
скрипт показал 17.97x от мировой цены $453, тогда как реалистичная
московская выручка за тот конкретный экземпляр (винил G) — 8–14 тыс ₽,
что даёт потолок ставки ~$21–25 по правилу 3x.

**Практическое правило: перед ставкой всегда пересчитывать 3x от
реалистичной цены продажи В МОСКВЕ, а не доверять марже из CSV.** Особенно
на высокомаржинальных находках — там оптимизм мирового рынка накапливается
сильнее всего.

**Обновление 30.08.2026: источник найден.** Разведка нашла JSON-эндпоинт
Мешка `POST /api/command/lots/get-items`, который отдаёт цены проданных
лотов, даты и грейды без авторизации. Клиент — `meshok_api.py`, разбор —
`docs/ru_market_notes.md`. Так что `margin_ru` теперь считается от
реального российского рынка, а не от мирового.

**Архив выкачан локально:** `meshok_archive.py` держит 146 575 проданных
лотов за 179 дней в `vinyl.db`. При прогоне eBay сеть к Мешку не нужна
вовсе, а вместо точечных цен появилась статистика рынка — она и
пересчитала часть допущений проекта (см. `docs/moscow_market_report.md`).

Ограничения, которые остаются в силе:

- **Окно — 179 дней, ровно полгода.** Больше архив не отдаёт.
  Потолок выдачи — 1400 записей на выборку, обходится партиционированием.
- **Медиана Мешка — цена на альбом, а не на пресс.** По каталожному номеру
  Мешок не ищет вообще (`PRLP 7049` → 0 результатов), потому что
  российские продавцы пишут исполнителя и альбом. Поправка на пресс берётся
  от Discogs через `beta` (`ru_price_model.py`), и `beta` **не
  откалибрована** по своим сделкам — поэтому `ru_confidence` не поднимается
  выше `medium`, сколько бы ни было продаж в выборке.
- **`ru_sold_n` важнее медианы.** Ноль продаж за окно ограничивает вердикт
  до WATCH независимо от любой маржи: ноль — это ответ, а не отсутствие
  данных. Две продажи за полгода — не рынок, а совпадение.

### Что архив изменил в допущениях

- **Премия за оригинальность в Москве — 1.19x**, а не кратная (измерено
  внутри одного альбома на 102 джазовых позициях). Среди лотов, которые
  окупают доставку в 3x, японских прессов больше, чем американских
  (138 против 107): в Москве платят за качество прессинга, а не за
  оригинальность. Значит `beta = 0.5` — верхняя граница, а не середина.
- **Коэффициенты грейдов теперь измеряются**, а не берутся из головы, и
  расходятся с прежними: Sealed даёт 4.99x к VG++ (в конфиге такой строки
  не было вовсе), NM 2.12 против 1.4, VG 0.91 против 0.55.
- **Средний джазовый лот не окупает доставку**: медиана джаза 1 300 ₽ при
  landed 1 270–2 115 ₽. Порог 3x перекрывают ~3% продаж, около 1 000 сделок
  в год на всём Мешке. Экономика живёт в хвосте, а не в потоке.

МаркетВинила закрыт для поиска его же robots-политикой, но его карточки
адресуются напрямую: id в URL МаркетВинила — это **id Discogs**
(`/release/<discogs_release_id>-<slug>`, проверено сверкой с API).
Реализация — `mv_release_url.py`. Из окружения агента их страницы пока
недоступны по egress-политике, см. §5 в `docs/ru_market_notes.md`.

### Остальные границы

- **Историю проданных лотов Discogs API не отдаёт вообще** — только
  текущую минимальную цену среди активных листингов. Отсюда degraded mode
  (median = low × 2) и запрет на PASS в нём. Цифры вида «медиана продаж
  $44.98 / последняя продажа 13.08.2026» берутся человеком со страницы
  Discogs в браузере — программного доступа к ним нет.
- **Watchers / views eBay недоступны** через Browse API (это данные
  Seller Hub). Работает только сигнал по bid_count, и то не всегда.
- **Фото скрипт не анализирует.** При `manual_review` ссылки на фото лота
  кладутся в колонку `photo_review_urls` — сверка каталожного номера с
  этикетки остаётся человеческим / vision-шагом.
- **Голые каталожные номера без буквенного префикса** («1588», «1577»)
  по-прежнему могут коллидировать между разными переизданиями. Теперь это
  хотя бы помечается `resolution_confidence = low` и понижает вердикт, а
  не проходит молча.
- **Бандлы** (несколько пластинок в одном листинге) не разбираются
  автоматически — логируются как «нужен ручной разбор».
- **Ансамблевая оценка не знает, какой именно пресс в лоте.** Митигация
  из §3 снижает доверие, но точную цену конкретного пресса без фото
  этикетки определить нельзя в принципе.

## 8. Уведомления и захват страниц

### `notify.py` — пуш на телефон без токена

Канал по умолчанию — **ntfy.sh**: ни регистрации, ни токена, ни ключа,
обычный POST на `https://ntfy.sh/<topic>`. Тема генерируется скриптом
(38 символов, ~160 бит), пишется в `.env` и больше не меняется.

```bash
python3 notify.py     # отправит тестовое и напечатает ссылку-подписку
```

Единственное действие человека во всём проекте — открыть эту ссылку на
телефоне (в браузере или в приложении ntfy).

**Тема фактически публична: кто знает строку, тот читает.** Поэтому она
длинная и случайная, а в пуш кладутся только ссылка на лот и цифры — без
учётных данных и без чего-либо лишнего. `.env` в `.gitignore`.

Драйвер `telegram` включается сам, без правки кода, как только в `.env`
появятся `TG_BOT_TOKEN` и `TG_CHAT_ID`.

### `tools/capture.py` — снятие фикстур настоящим браузером

```bash
python3 tools/capture.py <url> <name>
```

Персистентный профиль (`.pw-profile`, хранит `cf_clearance`), ожидание
селектора-признака контента вместо `sleep`, детект и переждание
Cloudflare-challenge, перехват всех JSON-ответов больше 1 КБ в
`tests/fixtures/xhr/` вместе с телом POST и заголовками.

В окружении агента включены транспортные флаги (`--ssl-version-max=tls1.2`,
без HTTP/2 и QUIC) — без них relay-прокси рвёт TLS-хендшейк Chromium на
любом адресе. На обычной машине они не нужны:
`CAPTURE_NO_TLS_WORKAROUND=1`.

### `tools/build_mv_release_index.py`

Собирает таблицу диапазонов id по 98 сайтмапам релизов МаркетВинила
Range-запросами по 400 байт. Нужен для `mv_release_url.py`.
