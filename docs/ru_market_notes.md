# Российский контур цен: что выяснено разведкой

Разведка 30.08.2026, вся — автоматическая, из окружения агента.
Отвечает на §3.2–3.4 ТЗ «автозахват» и содержит фактический отчёт по §1.

---

## 0. Короткий вывод, если читать одну секцию

1. **МаркетВинила: поиска для нас нет, но он и не нужен.** Path-формы
   поиска не существует, query-строки запрещены их же robots. Зато
   **id в URL МаркетВинила — это id Discogs**, и карточка релиза лежит по
   вычислимому адресу `/release/<discogs_release_id>-<slug>`. Резолвер уже
   знает release_id, значит URL карточки получается формулой, а не поиском.
2. **Мешок: найден JSON-эндпоинт, HTML-парсер не нужен.**
   `POST /api/command/lots/get-items` отдаёт цены, даты, грейды и статус
   продажи без авторизации и без единого обязательного заголовка.
3. **Основным источником цен становится Мешок** — как и предполагала
   вторая формулировка развилки в ТЗ.
4. **Цены МаркетВинила из этого окружения недоступны** — не из-за антибота,
   а из-за политики egress: challenge-хост Cloudflare заблокирован
   прокси. Подробности и готовая команда — §5.

## 1. Мешок — приоритетный путь (§3.1)

### Эндпоинт

```
POST https://meshok.net/api/command/lots/get-items
Content-Type: application/json
```

Найден не подбором: `page.on("response")` в `tools/capture.py` перехватил
его при обычной загрузке страницы категории. Сырые ответы и перехваченные
запросы лежат в `tests/fixtures/xhr/`.

Соседние эндпоинты того же семейства (`/api/command/<домен>/<действие>`):
`lots/get-lot-by-id`, `lots/get-lot-bids`, `lots/get-recent-lots`,
`categories/get-items`, `localization/get-overrides`,
`dicts/get-popular-cities.bin`.

### Обязательные заголовки и куки: НИКАКИХ

Браузер шлёт `x-hash`, `meshok-correlation-id`, `x-timeout` — сервер их
**не проверяет**. Запрос из `requests` без единой куки возвращает 200.
Авторизация не нужна ни для активных лотов, ни для завершённых.
Это и есть причина, по которой HTML-парсер Мешка писать нельзя (§6 ТЗ):
JSON переживёт редизайн, селекторы — нет.

### Параметры

Полный набор полей фильтра обязателен — отсутствующее поле валидатор
считает ошибкой, поэтому в `meshok_api.FILTER_DEFAULTS` они перечислены
явно, пусть и со значением `null`. Значимые:

| поле | значение |
|---|---|
| `categoryId` | **2211** — «Пластинки» (2 046 996 лотов). Найдено через `categories/get-items`, не подобрано |
| `searchString` | строка поиска, см. ограничение ниже |
| `status` | `active`, `activeOrDelayed`, `delayed`, `ended`, `endedOrDeleted`, `deleted` |
| `showOnly` | массив; **`["finishedAndSold"]` = «искать в успешных завершённых»** |
| `soldStatus` | `sold` / `notSold` — **только в sellerMode**; в режиме покупателя API отвечает `trying to apply soldStatus filter in buyer mode` |
| `type` | `auction`, `fixedPrice`, `liveAuction` |
| `condition` | `New`, `Used`, `NotAvailable`, `0`, `1`, `2` |
| `page` / `pageSize` | pageSize **20..200** |
| `sort` | `{"field":"endDate","direction":0|1}` |

Валидатор возвращает HTTP **418** с разбором по полям и сам перечисляет
допустимые значения — именно так эта таблица и получена. Поэтому клиент
ошибку валидатора **не глотает**: её текст и есть документация API.

### Что приходит в ответе (и почему это важно)

Один лот несёт: `price` / `normalizedPrice` / `startPrice` (₽),
`endDate` / `beginDate` (ISO UTC), `type`, `bidsCount`, **`soldQuantity`**
(>0 = продан), `city`, `delivery`, `seller`, `tags`, и —

**`additionalProperties` с грейдами прямо в списке результатов:**
«Состояние» (propertyId 446) и «Конверт» (456), значения вида
`Sealed` / `Near Mint` / `EX` / `VG`.

Это ответ на вопрос §3.4: **грейд виден в списке, отдельный запрос на
каждый лот не нужен.** Экономия — по запросу на лот выборки, то есть
десятки запросов на один релиз. Тест `test_meshok_api.py` фиксирует это
утверждение: если Мешок когда-нибудь уберёт грейд из списка, тест
покраснеет здесь, а не прод — на живом прогоне.

### Ограничение, которое меняет архитектуру поиска

**По каталожному номеру Мешок не ищет.** Замерено:

| запрос | завершённых лотов |
|---|---|
| `PRLP 7049` | 0 |
| `Prestige 7049` | 0 |
| `Bennie Green Walking Down` | 0 |
| `Miles Davis Steamin` | 4 |
| `Red Garland` | 20 |

Российские продавцы пишут в заголовке исполнителя и альбом, а не catno.
Значит запрос строится как «Artist Album», и это **принципиально менее
точно, чем catno**: конкретный пресс по такому запросу не отличить.

Практическое следствие для расчёта маржи: `ru_sold_median_rub` — это цена
**на альбом в среднем по прессам**, а не на тот пресс, что лежит в лоте
eBay. Для японского пресса 1975 г. и американского оригинала 1957 г. Мешок
вернёт одну и ту же выборку. Это надо помнить ровно так же, как «ансамблевую
ошибку ликвидности» на стороне Discogs, и по той же причине: обе завышают
маржу на культовых альбомах.

### Глубина архива (§3.4) — замерено, не оценено

| выборка | глубина |
|---|---|
| `showOnly=["finishedAndSold"]` (успешные продажи) | **179 дней, ровно полгода** |
| `status="ended"` (все завершённые, включая непроданные) | **365 дней, ровно год** |

Три независимых запроса упираются в одну и ту же дату:

| запрос | найдено | самая старая продажа |
|---|---|---|
| `Blue Note` | 294 | 2026-03-04 (179 дней) |
| `Miles Davis` | 381 | 2026-03-04 (179 дней) |
| `Coltrane` | 240 | 2026-03-04 (179 дней) |

**Окно расчёта `ru_sold_median_rub` — 6 месяцев.** Больше взять неоткуда,
и растягивать окно в конфиге бессмысленно: данных за пределами полугода
просто нет.

### Пагинация и потолок выдачи (§3.4)

- `page` + `pageSize` (макс. 200), плюс курсор `lastSortValues` в ответе.
- **Жёсткий потолок выдачи: 7 страниц × 200 = 1400 результатов.** На
  широких запросах (`jazz`, `Deep Purple`) выборка упирается в 1400 и
  обрезается по дате — то есть на слишком общем запросе медиана считается
  по последним неделям, а не по полугоду. Запрос должен быть узким.

### Лимиты и антибот-реакция (§3.4)

Около 60 запросов с паузой 1.2–1.5 с: ни одного 429, ни капчи, ни
замедления. Cloudflare на Мешке нет вообще. Специально частоту не
повышали — ломать чужой сайт ради замера верхней границы неуместно;
в `meshok_api.THROTTLE_S` оставлено 1.5 с.

### Геопривязка выдачи

Сайт определяет регион по IP: из этого окружения выдача помечена как
«Вашингтон + доставка». На стоимость лотов это не влияет (`price` тот же),
но влияет на блок доставки и на порядок сортировки по умолчанию.
С машины в России картина будет отличаться — при сверке цифр это
надо учитывать.

### URL-формы

- Категория: `https://meshok.net/good/2211`
- Поиск: `https://meshok.net/listing?good=2211&search=<запрос>`
- «Успешно завершённые»: тот же URL c `a_o=25`
- Лот: `https://meshok.net/item/<id>`
- Без `/en/`-префикса сайт 302-редиректит на него по гео; на API это
  не распространяется (`meshok-locale: ru` в заголовке достаточно).

## 2. МаркетВинила — развилка §3.2 решена

### Вывод: **path-формы поиска нет**

Формально — вторая формулировка из ТЗ. Доказательство не по кодам
ответов (их закрывает Cloudflare), а по их собственному сайтмапу, который
Cloudflare отдаёт без challenge:

- `sitemap-base.xml` перечисляет **весь не-товарный контур сайта**: `/`,
  `/about`, `/articles`, `/article/<N>`, `/cart`, `/contacts`,
  `/event/<N>`, `/events`, `/marketplace`, `/shop/<N>`, `/shops`,
  `/support`, `/user/<N>`. **Ни одного `/search`-пути.**
- В `robots.txt` для группы `*` стоит `Disallow: /search` — то есть поиск
  у них существует, но как `/search?...`, с query-строкой.
- Для нашей группы (AI-ассистенты) стоит `Disallow: /*?` — ровно эта форма
  нам и запрещена.

Итого: поиск по МаркетВинила коннектору недоступен в рамках их же правил.
`test_robots_policy.py` фиксирует это исполняемо — попытка сходить по
`/search?q=...` падает **до** обращения к сети.

### Но развилка оказалась лучше, чем предполагало ТЗ

ТЗ предполагало, что соответствие «Discogs-релиз → URL карточки» придётся
**копить по мере встречаемости**. Этого не нужно.

**Идентификаторы МаркетВинила — это идентификаторы Discogs.** Сверено с
Discogs API:

| URL МаркетВинила | Discogs |
|---|---|
| `/release/1-The-Persuader-Stockholm` | release 1 = The Persuader — Stockholm |
| `/release/3-Josh-Wink-Profound-Sounds-Vol-1` | release 3 = Josh Wink — Profound Sounds Vol. 1 |
| `/release/9-Blue-Six-Pure` | release 9 = Blue Six — Pure |
| `/master/125-Earth-Leakage-Trip-Psychotronic-EP` | master 125 = Earth Leakage Trip — Psychotronic EP |
| `/label/1-Planet-E` | label 1 = Planet E |

Значит URL карточки **вычисляется** из release_id, который резолвер уже
знает. Реализовано в `mv_release_url.py`.

Slug берётся из сайтмапов, а не конструируется: правила транслитерации и
обрезки у них свои, угадывать — источник тихих 404. Сайтмапы отсортированы
по id, поэтому индекс — таблица «последний id в файле», собранная
Range-запросами по 400 байт (`tools/build_mv_release_index.py`,
98 файлов, максимальный id 38 185 830). Нужный файл находится бинарным
поиском и кэшируется.

Отсутствие релиза в каталоге — **нормальный исход**, не ошибка: у
МаркетВинила заведомо не все релизы Discogs (например, release 2119390,
Mariachi Brass, отсутствует, хотя соседние id есть). Это значит лишь
«цены МаркетВинила по этому релизу нет».

Масштаб каталога по сайтмапам: 216 файлов товаров (`/product/`),
98 файлов релизов, 33 артистов, 29 лейблов, 9 мастер-релизов —
по 5000 записей в файле.

### Гость против логина (§3.3)

**Проверить не удалось.** Не из-за антибот-эвристик, а потому, что
HTML-страницы МаркетВинила из этого окружения недоступны в принципе
(§5). Реализация уже сделана так, как велит ТЗ, и включится сама:
`MV_LOGIN` / `MV_PASSWORD` читаются из `.env`, при их отсутствии
коннектор работает в гостевом режиме и помечает такие цены пониженным
`ru_confidence`. Учётные данные в коде не спрашиваются.

Фикстуры `mv_search.html`, `mv_release.html`, `mv_release_guest.html`
**не сняты** — вместо них лежит `mv_search_blocked.html` — настоящая
страница challenge как документальное свидетельство.

### robots.txt — тонкость, которую нельзя потерять

Апекс `marketvinila.ru` и `en.marketvinila.ru` отдают **разные** robots.
HTML-страницы 301-редиректятся на `en.`, а у него сверху добавлен
Cloudflare Managed блок:

```
User-agent: ClaudeBot
Disallow: /
```

`Claude-User` в этом блоке **не назван**, поэтому наш UA остаётся
разрешённым авторской группой «AI-ассистенты: доступ разрешён».
Но переключать `USER_AGENT` на `ClaudeBot` нельзя — это будет прямое
нарушение. Предупреждение продублировано в докстринге `ru_market.py`,
чтобы его не потеряли при рефакторинге.

## 3. Что из этого следует для расчёта маржи

`margin_ru` считается от **Мешка**. МаркетВинила — уточняющий источник по
прямой ссылке на карточку, когда релиз в их каталоге есть.

Три поправки, которые надо держать в голове одновременно:

1. **Окно — полгода, не год.** Больше данных нет.
2. **Медиана Мешка — это цена на альбом, а не на пресс.** Поиск по
   «Artist Album» не различает японский пресс 1975 г. и американский
   оригинал 1957 г.
3. **`ru_sold_n` важнее самой медианы.** Две продажи за полгода — это не
   рынок, а совпадение; ставку по такой выборке делать нельзя. Поэтому
   `summarize()` отдаёт `ru_sold_n` и границы диапазона рядом с медианой,
   а не одну цифру.

## 5. Отчёт по §1: почему браузер не взял МаркетВинила

По правилу §1 — не перекладывать на человека, а изложить факты.

### Что удалось починить самому

Chromium в этом окружении не открывал **ни одного** адреса, включая
`example.com`, при том что `curl` на том же URL отдавал 200:

```
Page.goto: net::ERR_CONNECTION_RESET at https://example.com/
```

Диагноз из `$HTTPS_PROXY/__agentproxy/status`:

```
kind:   ws_closed_mid_exchange
detail: tunnel closed (code 1006, Connection ended) after 6s;
        1729 B sent, 39 B received, client reading
```

ClientHello уходит, ответ не доходит — relay-прокси не переносит
TLS-1.3-хендшейк Chromium. Перебор конфигураций:

| конфигурация | результат |
|---|---|
| headless по умолчанию | ERR_CONNECTION_RESET |
| `proxy={"server": $HTTPS_PROXY}` | ERR_CONNECTION_RESET |
| `--disable-features=EncryptedClientHello` | ERR_CONNECTION_RESET |
| `--disable-http2 --disable-quic` | ERR_CONNECTION_RESET |
| **`--ssl-version-max=tls1.2` + оба выше** | **200 OK** |

Это настройка транспорта, а не маскировка клиента: User-Agent, платформа
и заголовки остаются браузерными по умолчанию, §6 не нарушен. Флаги
зашиты в `tools/capture.py` и снимаются переменной
`CAPTURE_NO_TLS_WORKAROUND=1` — на машине пользователя они не нужны.

После этого браузер заработал полностью: Мешок отрисовывается, XHR
перехватываются, фикстуры снимаются, `api.discogs.com` отвечает.

### Что починить нельзя и почему

На `en.marketvinila.ru` браузер садится на Cloudflare-интерстишл
(`Один момент…`, он же `Just a moment…`) и не сходит с него. Причина —
не антибот-эвристика, а политика egress:

```
2026-08-30T16:14:14Z  connect_rejected
brunhild.challenges.cloudflare.com:443
gateway answered 502 to CONNECT (policy denial or upstream failure)
```

Turnstile обязан сходить на `*.challenges.cloudflare.com`, чтобы выдать
`cf_clearance`. Этот хост запрещён egress-политикой сессии. Значит
challenge **не может завершиться ни при какой настройке браузера** —
ни headless, ни headed под `xvfb-run` (проверено обе), ни с
персистентным профилем, ни с 90-секундным ожиданием.

Инструкция прокси на такой случай однозначна: «Do not retry or route
around it — report the blocked host». Обходить это через сторонние прокси
и антибот-сервисы прямо запрещено §6 ТЗ. Поэтому — отчёт, а не обход.

### Факты по последней попытке

```
requested : https://marketvinila.ru/marketplace
final     : https://en.marketvinila.ru/marketplace
HTTP      : 403 (через curl -L), goto timeout 60 s (через Chromium)
title     : Один момент…
body      : 27 553 байта, tests/fixtures/mv_search_blocked.html
блокирует : brunhild.challenges.cloudflare.com:443 — 502 от egress-шлюза
```

Первые ~500 символов body — стандартная заглушка Cloudflare:

```html
<!DOCTYPE html><html lang="en-US" dir="ltr"><head><title>Один момент…</title>
<meta http-equiv="Content-Type" content="text/html; charset=UTF-8">
<meta http-equiv="X-UA-Compatible" content="IE=Edge">
<meta name="robots" content="noindex,nofollow">
<meta name="viewport" content="width=device-width,initial-scale=1">
<meta http-equiv="content-security-policy" content="default-src 'none';
  script-src 'nonce-gcKtkZV5yBh2oWyRsED84v' 'unsafe-eval'
  https://challenges.cloudflare.com; script-src-attr 'none'; style-src …
```

Последняя строка — прямое подтверждение диагноза: CSP страницы разрешает
скрипты только с `challenges.cloudflare.com`, а именно этот хост egress
и не пропускает.

### Команда, которой это проверяется с машины без такой политики

```bash
CAPTURE_NO_TLS_WORKAROUND=1 python3 tools/capture.py \
  https://marketvinila.ru/release/1-The-Persuader-Stockholm mv_release
```

Профиль в `.pw-profile` сохранит `cf_clearance`, и повторные запуски
пойдут без задержки. Того же скрипта хватит и для `mv_release_guest`
(чистый профиль — удалить `.pw-profile`).

**Но это не блокирует проект.** Цены берутся с Мешка, где всё работает
из этого окружения; МаркетВинила подключается по прямым path-URL, которые
уже вычисляются, как только его страницы станут доступны.

## 6. МаркетВинила: найденная дыра и почему ею не пользуемся (01.09.2026)

При подготовке §4.4 «Установок» обнаружился путь, отдающий цены без
Cloudflare. Фиксирую его вместе с решением, чтобы к вопросу не возвращаться.

### Что найдено

Апекс `marketvinila.ru` отдаёт настоящую карточку товара — с ценами и
грейдами — если к пути дописать суффикс, не попадающий под правило
редиректа:

```
/product/1202107-Little-Boots-Hands.json  -> 200, 89 КБ
   700 ₽ (VG+/VG+)   1 100 ₽ (NM/VG+)   5 200 ₽ (NM/NM)
```

### Почему это дыра, а не другая дверь

Проверено:

- канонический адрес, который сайт **сам публикует в своём sitemap**, —
  это чистый путь `/release/<id>-<slug>` без суффикса;
- этот путь **безусловно** редиректится на `en.marketvinila.ru`:
  ни `Accept-Language: ru`, ни cookie языка, ни `ru.` поддомен на это
  не влияют — редирект геозависимый;
- `en.` закрыт Cloudflare Turnstile (403);
- вариант с суффиксом нигде не опубликован и работает ровно потому,
  что правило редиректа его не ловит.

Настоящего публичного интерфейса нет: `api.marketvinila.ru` отвечает
(`{"message":"Not found."}` на всё), но ни один путь не отдаёт данных;
эндпоинта мобильного приложения не обнаружено.

### Решение

**Не пользуемся.** Три контрольных вопроса владельца дали формальное
«нет» (челлендж не решается и не эмулируется, куки и токены ниоткуда не
берутся, query-строки не используются), но по существу это обход защиты,
которую оператор поставил, а не вход в дверь, которую он открыл.
Цена вопроса не этика, а бан домена, от которого зависит верхний сегмент.

§4.4 закрывается запуском `tools/mv_price_survey.py` с машины, где
Turnstile проходит честно. Код готов и ходит по каноническому адресу.

### Замеренное ограничение метода

План выборки построен (`docs/mv_survey_plan.json`, 74 позиции), но
покрытие каталога оказалось ниже ожидаемого:

| страта | позиций | резолвится в release_id | есть карточка |
|---|--:|--:|--:|
| 3.5–6 тыс | 20 | 14 | 5 |
| 6–10 тыс | 20 | 15 | 4 |
| 10 тыс+ | 14 | 9 | 1 |
| джаз | 20 | 15 | 8 |
| **итого** | **74** | **53** | **18** |

Две вещи, которые из этого следуют:

1. **Сопоставление по одному release_id хрупко.** «Исполнитель + альбом»
   резолвится в КАКОЙ-ТО релиз Discogs, а МаркетВинила может держать
   другой пресс того же альбома. Правильнее искать по мастер-релизу и
   принимать любой из его прессов — это и есть первая правка перед
   боевым запуском.
2. **Покрытие джаза выше всех (8 из 15 против 1 из 9 в страте 10 тыс+).**
   Это косвенно поддерживает гипотезу, ради которой срез и задуман:
   МаркетВинила — площадка джазовых коллекционеров, и вердикт «джаз мёртв»,
   вынесенный по Мешку, вполне может там перевернуться.
