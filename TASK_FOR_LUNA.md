# Barik.am — техническое задание для «Луны»

**Аудит от 13 ноября 2026 года. Итоговая оценка — 7,3/10.**

## 1. Контекст и цель

Ты дорабатываешь Barik.am, портал для изучения восточноармянского с шестью языками интерфейса. Сайт объединяет гостевой урок, словарь, алфавит и пропись, разговорник, курс «Путь Граната» и Premium. Веб-приложение использует обычный JavaScript, HTML и CSS. Из той же базы собирается приложение Capacitor. Python-генераторы готовят публичный сайт, отдельные индексируемые страницы и service worker. PHP обслуживает аккаунт и оплату.

Цель этой итерации — дать гостю предсказуемый путь со страницы поиска до первого упражнения, исправить доступность уроков и сократить задержку до взаимодействия. Сохрани бренд, армянское написание и транскрипцию, двухголосую озвучку, структуру учебных данных, локальный прогресс, SEO-адреса и текущие границы Premium.

**База сравнения.** Ветка `codex/audit4`, коммит `3ec1e99b4e64e2978fbc5f8466d49618bd592214`. Релиз на этот SHA успешен. Публичные `app.css` и `i18n.js` совпали с исходниками, публичный `app.js` — с исходником после подстановки версий двух ленивых ресурсов. Сопоставление относится к этим файлам. Локальный `HEAD` выбранной рабочей копии старше и содержит существующие пользовательские правки. Перед реализацией сравни свежую ветку с указанным SHA и проверь статус своей копии. - **Изменение.** При смене шага фокусируй локализованный заголовок или группу вопроса с `tabindex="-1"`. При фоне обновляй только изменившийся узел либо восстанавливай активный контрол и позицию ввода. У прогресса задай доступное имя и локализованный текст «Шаг X из Y». Визуально можно сохранить шкалу завершённых шагов. Назови аудиокнопки по действию и добавь короткое объявление правильного/неправильного ответа. #### C3 · P1 — Сделать загрузку разговорника и офлайн-сохранение достоверными

- **Доказательство по коду.** `pbLoad()` при сетевом исключении сбрасывает только флаг загрузки. На открытом экране остаётся «…» без повторного действия. При HTTP-ошибке `render()` через `phrasesHTML()` снова вызывает загрузку. `pbOffline()` игнорирует неудачные запросы, затем выставляет `PBS='ok'`. HTTP 404 также разрешает Promise от `fetch`. Публичный `sw.js` кладёт в аудиокэш только полный HTTP 200 с аудио MIME, поэтому сообщение об успехе может расходиться с реальным состоянием.
- **Где.** `apps/barik/www/js/app.js`, `pbLoad()`, `phrasesHTML()`, `pbOffline()` около 1148–1164. `apps/barik/tools/build_site.py`, шаблон `SW`. Строки интерфейса `pb*` в `i18n.js`.
- **Изменение.** Введи состояния «загрузка», «готово», «ошибка» и ручной повтор. Считай завершённые загрузки по фактическим пригодным записям для выбранного голоса. Учитывай отсутствие активного service worker, заполнение хранилища, частичный успех и смену голоса. Отображай успех только после подтверждённой записи в кэш, которую можно воспроизвести офлайн.
- **Приёмка.** На собранном сайте подставь отклонение `fetch`, HTTP 404, HTML вместо MP3 и частичный набор. При отказе нет автоматического цикла. После ручного повтора догружаются отсутствующие записи. Успешно сохранённые фразы играют после отключения сети и повторного открытия на том же профиле, включая iOS Safari или отдельную отметку о том, что он ещё не проверен. [Публичный service worker](https://barik.am/sw.js)

2. **Исправь C1 → C2 → C3 отдельными изменениями.** В каждом случае сначала зафиксируй конкретное воспроизведение, затем сделай минимальную правку в источнике и запусти целевой тест. 3. **Сделай U1 → U2 → U3.** Сохрани текущие строки локального состояния, правила интервального повторения и значения Premium. Проверь языки RU/EN/FR/ES/DE/PT, тему, клавиатуру, реальные iOS/Android при наличии и сетевой отказ. Для недоступных устройств явно укажи, что проверялось только эмуляцией.

6. **Проверь итоговый дифф.** В отчёте укажи выполненные ID, файлы, воспроизведения до/после, результаты тестов и метрик, а также всё оставшееся непроверенным. ### Не проверено на реальном устройстве или аккаунте

Физические устройства iOS/Android, работа скринридера, запись с микрофона, офлайн после установки с чистым кэшем, реальная покупка и статус индексации в Search Console не проверялись. Лабораторный прогон не заменяет полевые Core Web Vitals.

Первый производственный запуск **43517247981** выложил сборку, но live guest check выявил гонку: поздний ответ аккаунта перерисовывал демо между третьим ответом и появлением кнопки продолжения. В `app.js` исправлена отложенная вставка: кнопка теперь находится в актуальном DOM после фонового рендера. В `test_site.js` добавлена проверка этой гонки; кандидатский полный набор прошёл.

Повторный релиз запущен штатным GitHub workflow на `codex/audit4`: полный набор проверок → `bash tools/ship.sh` → live guest checks. Результат повторной публикации и живой проверки фиксируется после завершения workflow.
